# Публикация демо через GitHub Pages

Источник сайта — только `site/`: главная страница index.html и существующий автономный pilot-dragon.html. Основной README остаётся документацией репозитория. CSV/миры/локальные отчёты в artifact не входят.

Workflow `.github/workflows/pages.yml` использует официальные actions: checkout v6, configure-pages v5, upload-pages-artifact v4 и deploy-pages v4. Build имеет contents:read; deploy — pages:write и id-token:write, environment github-pages. Группа concurrency pages предотвращает одновременные deployment; выполняющийся deployment не отменяется новым push. Секреты не нужны. Источник версий: [официальная документация GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

После проверки PR:

1. В FunGluck/TickSense откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions** вместо Deploy from a branch. При необходимости нужны права администратора репозитория.
2. Объедините PR в main. Агент не выполняет автоматический merge.
3. В Actions дождитесь успешного **Deploy TickSense demo to Pages**. При необходимости запустите его вручную через Run workflow на main. До merge feature-ветка автоматически не публикуется.
4. Проверьте адреса https://fungluck.github.io/TickSense/ и https://fungluck.github.io/TickSense/pilot-dragon.html. Нажмите «Посмотреть пример отчёта», проверьте графики, выбор сессии, масштабирование и мобильную ширину. Успешный push/PR сам по себе не доказывает публикацию.

## Обновление отчёта одной командой

Из корня проекта, после установки analysis/requirements.txt в локальное окружение:

```powershell
.\.venv\Scripts\python.exe scripts/generate_demo.py
```

Скрипт не обращается к сети и не выполняет публикацию. Он вызывает существующий analysis.analyze и общий Dashboard, записывая только site/pilot-dragon.html. На другой машине нужны исходные разрешённые CSV в datasets/; они не включены в Git. Если файлов нет или SHA-256 отличается, генерация останавливается до изменения отчёта. Нельзя заменять их данными участников Pilot. Для повторения используйте те же версии зависимостей анализа; при обновлении scikit-learn сравните предсказания.

### Происхождение данных и режим анализа

Старое демо внесено коммитом c53a006. Все 872 публичных точки соответствуют Dragon Run.csv. Восстановленный исходный TRAIN — metrics-v2-2026-11-01.csv (145 измерений): повторный расчёт на нём совпал со всеми ML-метками старого демо, максимальная разница score около 5×10⁻¹¹ (округление встроенного JSON). Поэтому сохраняется старый двухфайловый режим TRAIN/TEST, а не вводится новое обучение на ранних 70% Dragon Run.

| Назначение | Локальный исходник | SHA-256 |
|---|---|---|
| Обучение | metrics-v2-2026-11-01.csv | f0e7a79e84a03cf83b779c5ed97f542aeed722d5284ad85d146364a170e78510 |
| Полная отображаемая история / TEST | Dragon Run.csv | 1664341aa0e065c09e65affc10e715cc47f7f4e0784d782e0d8159c6e7b93267 |

Эти контрольные суммы проверяются скриптом. Данные первого реального участника Pilot не используются. В публичный HTML попадают только уже разрешённые демонстрационные данные, с базовыми именами исходников вместо локальных абсолютных путей. Публиковать CSV, приватные JSON/HTML или весь datasets/ не требуется.

Результат текущей генерации: 872 точки, 1 ML-метка (сохранена), 44 статистических отклонения (сохранены), 1 ML-период, 0 пороговых эпизодов, GREEN. Пустые состояния раздела нагрузки здесь ожидаемы. Показатели вычисляет анализатор — эти числа не подставляются в генератор. Результат 97 ML-меток, полученный ранее для Dragon Run в Pilot-режиме 70/30, относится к другому обучению и не является регрессией публичного демо.

HTML использует актуальные шаблон, CSS и JS: полную отображаемую историю, сгруппированные необычные периоды, переключатели, навигатор и закрытые технические подробности. Цвет меняется только у прежнего фонового градиента; декоративного ядра и анимации нет. Главная страница сохраняет прежнюю кнопку и адрес pilot-dragon.html, без редизайна. Скриншотов или внешних превью на ней нет.

После генерации: python -m unittest discover -s analysis, node --check analysis/dashboard/dashboard.js, git diff --check. Статические тесты публичного артефакта не требуют локальных CSV; проверяют актуальность встроенных ресурсов, исходные результаты и отсутствие сетевых ресурсов/абсолютных путей. Для визуальной проверки откройте HTML локально или разрешённый HTTP-preview и проверьте переключатели, раскрытие периодов, сессии, масштаб и мобильную ширину. Node DOM/Canvas tests не заменяют эту проверку.

Публикация остаётся прежней: после одобренного merge в main Pages workflow автоматически загружает site/ и развёртывает сайт. До merge PR новая версия не опубликована. Не запускайте workflow_dispatch ради обхода согласования.

### Проверка подготовленного обновления

Локальный HTTP-preview вернул 200 и был открыт в настоящем Chromium-браузере. Проверены ML-checkbox, клавиатурное изменение начала диапазона, сброс масштаба, подсказка Canvas, выбор «Сессия 1» с сохранением checkbox, раскрытие необычного периода и технических подробностей. Консоль браузера не показала ошибок. Через DOM подтверждены GREEN, исходный зелёный radial-gradient и отсутствие .energy-core. На viewport 390×844 ширина документа не превысила viewport; скриншот не получен из-за тайм-аута captureScreenshot, поэтому полная визуальная оценка мобильного вида остаётся ручной. Временный сервер остановлен.

67 Python-тестов пройдены, включая проверки публичного HTML и отказа от подменённых входов. JavaScript проверен синтаксически и существующими Node-тестами взаимодействий. Текущие публичные URL ответили HTTP 200, но до merge они продолжают показывать прежнюю версию.
