# Производительность автономного Dashboard

Стенд использует синтетические данные с фиксированным seed. В нём есть несколько сессий, переходы через полночь UTC, пробелы, одиночные пики MSPT, серии низкого TPS и метки обоих детекторов. Замер генерации начинается после анализа, поэтому он относится к HTML.

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_dashboard.py --output reports/dashboard-after
git worktree add --detach ../TickSense-dashboard-baseline d399bc7
.\.venv\Scripts\python.exe scripts/benchmark_dashboard.py --source ../TickSense-dashboard-baseline --output reports/dashboard-before
```

Для отдельного замера пиковых выделений Python добавьте `--memory`. Он включает `tracemalloc`, который влияет на длительность генерации. Node.js измеряет разбор данных и обработчики Dashboard с тестовыми заменами DOM и Canvas. Для браузерного замера служит локальный HTTP-сервер с синтетическими отчётами и метка после завершения первого построения.

Генерация включает подготовку, сериализацию и запись. На 100 000 измерений они заняли 4,69 / 1,09 / 0,46 с до оптимизации и 0,62 / 0,49 / 0,009 с после. При первом построении в Chrome на 100 000 измерений время от начала навигации до завершения JavaScript составило 1,70 с до изменений и 0,55 с после. Для 150 000 измерений новый отчёт построился за 1,08 с. Это отдельные замеры на одном компьютере. Браузерный замер включает загрузку с локального сервера и работу JavaScript, до представления кадра на экране.

На 100 000 измерений пиковые выделения Python по `tracemalloc` снизились с 299,1 до 95,1 МБ. При первом построении отчёта на 100 000 измерений число DOM-элементов сократилось с 7 918 до 1 730. Моментальный замер JS heap в Chrome, до стабилизации сборщика мусора, составил 49,5 МБ до и 64,8 МБ после. Снижение расхода памяти браузера не подтверждено. При 150 000 измерений тестовый Node также показывает, что время полного старта и затратный первый zoom могут колебаться между прогонами.

## Как строятся графики

HTML хранит все точки по столбцам. Крупный встроенный JSON сжимается gzip и кодируется base64. Распаковка использует встроенный `DecompressionStream` актуальных браузеров и работает без сетевых зависимостей. Небольшие отчёты используют обычный JSON.

Границы видимого диапазона находятся двоичным поиском. При плотной истории в каждом временном интервале шириной в пиксель рисуются первая, последняя, минимальная и максимальная точки каждого непрерывного отрезка. Одиночные пики MSPT и просадки TPS остаются видны. Маркеры каждого типа группируются отдельно. При достаточном увеличении и в подсказках доступны исходные точки. Карточки событий и техническая таблица разбиты на страницы.

Сводка, состояние сервера, пороговые эпизоды и ML используют полные результаты анализа. Формат отдельного JSON-отчёта сохраняется.
