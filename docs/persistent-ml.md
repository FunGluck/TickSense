# Сохраняемая модель Isolation Forest

TickSense обучает модель отдельной командой. Анализатор загружает выбранную версию и оценивает каждое измерение с доступными MSPT, онлайном и TPS. Порядок признаков фиксирован — `mspt_avg`, `players_online`, `tps_1m`. Предобработка модели тождественная. Параметры сохраняют конфигурацию анализатора, включая 100 деревьев, `contamination=0.05`, `max_samples="auto"` и `random_state=42`.

## Обучение первой версии

Выполняйте команды PowerShell из корня репозитория с настроенной средой Python. Храните CSV одного сервера в отдельной локальной папке. В режиме `--data-dir` порядок определяется именами файлов. Используйте имена с датами в формате `YYYY-MM-DD` или передайте `--files` в явном хронологическом порядке.

```powershell
.\.venv\Scripts\python.exe analysis/train_model.py --data-dir datasets/VanillaNight --server-id VanillaNight --output models/vanillanight-v1.joblib
```

```powershell
.\.venv\Scripts\python.exe analysis/train_model.py --files datasets/day-1.csv datasets/day-2.csv --server-id my-server --output models/my-server-v1.joblib
```

Команда требует CSV v2, проверяет хронологию и выделяет сессии по сбросам `elapsed_ms`. Переход через полночь UTC сам по себе не создаёт сессию. Перекрывающиеся файлы следует исправить у источника. Точные дубликаты внутри принятого периода отражаются в отчёте качества и сохраняются по действующей политике анализатора. При накоплении истории храните по одной копии каждого дневного файла.

Модель обучается на пригодных строках из первых 80% истории. Граница при необходимости сдвигается до окончания группы одинаковых временных меток. Последний участок используется для независимой хронологической проверки и остаётся за пределами обучения сохранённой версии. В отчёте проверки есть доля ML-аномалий, квантили `decision_function` и число ML-периодов, в том числе периодов с пороговыми сигналами. Для оценки точности нужны размеченные данные.

Команда создаёт пару `.joblib` и `.metadata.json`. Храните их вместе. Метаданные содержат версии окружения, SHA-256 модели, параметры, границы обучения и проверки, контрольные суммы входных CSV в порядке чтения и отчёт качества. Укажите неперсональный идентификатор сервера в `--server-id`. Существующие файлы версии защищены от перезаписи.

## Анализ новых CSV

```powershell
.\.venv\Scripts\python.exe analysis/analyze.py --pilot-files datasets/new-day-1.csv datasets/new-day-2.csv --model models/vanillanight-v1.joblib --html reports/vanillanight-new.html --json reports/vanillanight-new.json --no-show
```

Используйте только доверенную локальную пару файлов. `joblib` основан на pickle и может выполнять код при загрузке. SHA-256 выявляет повреждение, а происхождение файлов проверяется отдельно. Загрузка требует совпадения версий Python, scikit-learn, NumPy, pandas, SciPy и joblib с метаданными. Для другой среды создайте новую версию в ней либо восстановите исходное окружение.

HTML показывает весь переданный период без границы TRAIN/TEST. Сведения о версии и охвате ML доступны в технических подробностях. Строка с пустым MSPT, онлайном или TPS сохраняется с недоступной ML-оценкой. Некорректные числа, отрицательные значения и отсутствующие обязательные столбцы приводят к ошибке проверки. Статистический детектор использует доступные предыдущие измерения внутри переданных файлов и сессий. Первые шесть наблюдений каждой сессии остаются без rolling-порога. Пороговые события и группировка ML-периодов строятся по действующим правилам. Загрузка модели не обращается к файлам обучения.

При запуске `--pilot-files` без `--model` действует прежнее разделение 70/30. В двухфайловом режиме первый позиционный CSV остаётся набором обучения, второй используется для оценки.

## Подготовка v2 и откат

Накапливайте новые дневные CSV того же сервера в хронологическом порядке. Запустите обучение с именем `models/vanillanight-v2.joblib` и тем же `--server-id`. Оставьте отдельные CSV для сравнения, начиная строго после конца обеих отложенных проверок.

```powershell
.\.venv\Scripts\python.exe analysis/train_model.py --data-dir datasets/VanillaNight --server-id VanillaNight --output models/vanillanight-v2.joblib
.\.venv\Scripts\python.exe analysis/compare_saved_models.py --models models/vanillanight-v1.joblib models/vanillanight-v2.joblib --files datasets/comparison-day.csv
```

Обе версии оценивают одинаковые строки. Сопоставьте доли аномалий, распределения оценок и эпизоды с пороговыми сигналами. Выберите версию явно в `--model`. Для отката снова укажите путь к v1. Каждый кандидат обучается с нуля, переход на новую версию выполняет оператор.

VanillaNight v1 отражает историю одного сервера. Изменение настроек, состава плагинов или обычной нагрузки может менять распределение признаков. Нагрузочные эксперименты в истории первой версии не размечены. Их строки не фильтруются по ML-меткам или пороговым сигналам.
