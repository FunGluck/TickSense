# Аудит перед v0.8.0 Pilot

Локальная проверка 02.11.2026. Это аудит исходников и тестовой сборки, не независимая сертификация, не production-гарантия и не измерение накладных расходов. Сервер Minecraft не создавался и не запускался.

## Сборщик

| Область | Наблюдение и предел проверки |
| --- | --- |
| Потоки | Scheduler Paper синхронный; TPS/MSPT/онлайн и world counts читаются только там. Worker читает свою YAML-конфигурацию, пишет CSV и журнал, не обращается к состоянию сервера |
| API | Java 21; Paper 1.21.4 compileOnly. Прямые World.getChunkCount/getEntityCount/getTileEntityCount, без NMS/reflection и ручного обхода сущностей или чанков. Внутренняя стоимость методов Paper требует измерения |
| Передача | Immutable record → ArrayBlockingQueue → worker. offer не ждёт свободной ёмкости; при переполнении отбрасывается новый снимок, счётчик потерь агрегируется раз в 30 с и в конце |
| Память | Очередь ограничена queue-capacity (1024 по умолчанию), растущего списка снимков нет. Ёмкость задаёт администратор: произвольно большие значения могут потребовать много памяти. Анализ Python читает весь CSV и формирует отчёт в RAM — это отдельный офлайн-процесс, не streaming |
| Завершение | Сначала отменяется задача, stopping запрещает новый сбор; worker опустошает очередь и закрывает writer. Главный поток ждёт до 3 с, затем interrupt. Зависшее неinterruptible IO может оставить daemon-поток до завершения процесса. Горячая повторная загрузка не поддерживается |
| Потери | При исправном диске штатное закрытие пытается дописать всё. Полной гарантии нет: очередь, IO-ошибка, deadline, kill и питание могут привести к потерям. flush каждой строки не является fsync. Shutdown может блокировать главный поток до 3 с только на этапе отключения |
| Диск | Файловые операции находятся в worker. Exception прекращает сбор с SEVERE; автоматически возобновляться он не будет. Журнал не свидетельствует, что измерения продолжаются после ошибки. Сбор прекращается, но plugin может оставаться enabled в Bukkit |
| CSV | Отдельная схема v2 и UTC-файлы. Заголовок проверяется до append. Исправлен риск склеивания новой записи с незавершённым хвостом: теперь отказ с сохранением файла. Полная валидация старых строк/восстановление не реализованы |
| Хранилище | Нет удаления старых файлов/квоты, администратор следит за диском. Каталог ограничен лексически папкой плагина; symlink/junction — ответственность администратора, это не файловая песочница. Один сервер/worker на каталог, блокировки между процессами нет |

Неизменённый стандартный интервал — 200 серверных тиков; это не гарантированные 10 реальных секунд. В onEnable сбрасывается служебный счётчик тиков. Общая архитектура и CSV-поля сохранены.

## Сеть, данные, приватность

По просмотру Java/Python/HTML-кода и поиску сетевых вызовов не найдено автоматической отправки телеметрии, bStats, HTTP-клиентов или сетевых ресурсов Dashboard. CLI только читает локальные CSV и пишет отчёты; HTML не использует fetch/CDN и имеет CSP с запретом соединений. Интернет нужен для получения Gradle/Maven/pip-зависимостей при установке/сборке. Загрузки зависимостей не являются отправкой серверных метрик.

12 полей CSV: timestamp_utc, elapsed_ms, tps_1m, mspt_avg, players_online, jvm_heap_used_bytes, loaded_chunks, entities_total, block_entities_total, jvm_heap_committed_bytes, gc_collection_count, gc_collection_time_ms. Нет имён/UUID/IP игроков, координат, чата или world seed. Агрегаты, UTC и выбранные имена файлов всё же могут раскрывать активность сервера. JSON содержит абсолютные пути; HTML — имена файлов, временные ряды и объяснения. Любую передачу контролирует администратор.

`git ls-files` подтвердил: datasets содержит только .gitkeep; нет отслеживаемых реальных CSV/JSON или готовых отчётов, единственный отслеживаемый HTML — шаблон без серверных данных. Проверен .gitignore для CSV, datasets, reports, dist, JAR, логов, окружений и типовых секретов. Правила игнорирования не защищают уже отслеживаемые файлы и не заменяют проверку staged diff.

Эвристический поиск ключей/токенов/приватных ключей в отслеживаемых текстовых файлах и diff всех 12 доступных коммитов не дал совпадений. Это не доказательство отсутствия всех секретов; не исследовались чужие учётные записи или внешние источники. Перед публикацией владелец дополнительно проверяет staged diff, историю и вложения. Файл LICENSE отсутствует: условия распространения должен определить владелец до публичной публикации; лицензия автоматически не выбиралась.

## Сборка и воспроизводимость

Обнаружены и выполнены реальные Gradle-задачи tasks, dependencies, clean, test, build. Wrapper использует Gradle 8.5, toolchain Java 21; локально Temurin 21.0.10+7, Windows. Версия `0.8.0-pilot` в Gradle — единственный источник для plugin.yml. JAR имеет фиксированные timestamps и воспроизводимый порядок записей согласно [механизму Gradle](https://docs.gradle.org/current/userguide/working_with_files.html#sec:reproducible_archives).

`clean test build --no-build-cache` успешен. Дополнительная сборка копии исходников в `.gradle/pilot-source-check-080` с `--no-build-cache --no-daemon --rerun-tasks` также успешна: SHA-256 совпал. У копии не было проектного кеша/outputs; пользовательский кеш Gradle и JDK общие. Полностью новая ОС/пустой GRADLE_USER_HOME с загрузкой из сети не проверялись. Paper API остаётся `1.21.4-R0.1-SNAPSHOT`: изменяемый артефакт и транзитивные зависимости ограничивают воспроизводимость на другом хосте. Wrapper distribution SHA отдельно не закреплён. Это известные ограничения Pilot, не заявление о bit-for-bit сборке в любой среде.

runtimeClasspath пуст. В compileClasspath только Paper API и его транзитивные библиотеки, предоставляемые Paper; test-зависимости — JUnit. В JAR проверены 6 class-файлов TickSense, Java class major 65, config.yml и plugin.yml. Нет классов Paper/JUnit, Python, CSV, HTML, приватных абсолютных путей или вложенных библиотек.

`analysis/requirements-pilot.txt` закрепляет три прямые зависимости реально использованного окружения: pandas 2.3.3, matplotlib 3.10.9, scikit-learn 1.7.2. Транзитивные зависимости и OS wheels не закреплены; полный локальный pip freeze сохранён в ignored `build/pilot-python-environment.txt`. Свежая pip-установка отдельно не выполнялась.

Артефакт: `build/libs/TickSense-0.8.0-pilot.jar`.

```text
SHA-256: 2abc8cde1d49e9072708a402dbd028cdb83a71e7b53c89894dafce6c82628743
```

Локальные сопроводительные файлы: `build/pilot-artifact.json`, `build/libs/TickSense-0.8.0-pilot.jar.sha256`. SHA относится именно к этой сборке.

## Результаты тестов

- 13 Java-тестов, без ошибок/пропусков: CSV и порядок 12 полей, GC -1, очередь, повторное открытие, UTC-ротация, старый/несовместимый заголовок, незавершённый хвост и ошибка файлового пути.
- 44 Python-теста, все прошли. Node.js 22.13.1 присутствовал, тесты логики Dashboard не пропущены. Проверены train/test, признаки, события, объяснения, JSON, XSS-экранирование, локализация, Canvas-навигация и прежние CLI-аргументы.
- Сгенерированы локальные HTML/JSON для эксперимента 118,33 мс (145 строк), Dragon Run (872), CSV v1 (365). JSON совпал с прежним 0.6: для 118 мс — по одному high_mspt/low_tps/elevated_mspt, для Dragon Run — 0, для v1 — один elevated_mspt. Это сигналы, не число доказанных лагов.
- Визуальная проверка реальным браузером не выполнена: доступный инструмент отклоняет file://. DOM/Canvas-заглушки не проверяют рендеринг, pointer capture реального браузера или сенсорное устройство.

## Оставшиеся ручные проверки перед передачей Pilot

- [ ] На восстановленной тестовой копии Paper 1.21.4/Java21 проверить запуск, первые строки, все поля и журнал.
- [ ] Проверить штатную остановку с очередью, продолжение того же дня, ротацию UTC, enabled=false и удаление JAR. Проверить отсутствие потерь по доступной диагностике, не обещая абсолютной гарантии.
- [ ] На отдельной тестовой копии проверить отказ доступа/нехватку диска, остановку сбора, диагностику и восстановление после устранения причины; не заполнять production-диск.
- [ ] Проверить мировые/GC-счётчики, нагрузку при большом числе миров/чанков и настройки паузы пустого сервера.
- [ ] Провести A/B/B/A по [методике](overhead-methodology.md), записать фактические накладные расходы и вариативность. Сейчас они **не измерены**.
- [ ] Открыть HTML через file:// в реальных настольном и мобильном браузерах: сессии, маркеры, события, resize, wheel/drag/cancel, клавиатура и русская типографика.
- [ ] Проверить сборку/установку зависимостей на другой чистой машине; принять решение о закреплении Paper SNAPSHOT/всех транзитивных зависимостей.
- [ ] Определить лицензию и границы пилота, проверить приватность вложений, SHA и метаданные, согласовать получателей.
- [ ] Только после отдельного подтверждения владельца создавать тег/Release и распространять JAR. Сейчас релиз/тег/коммиты/push не выполнялись.

GitHub Actions в рамках подготовки не добавлялись: существующие проверки выполнены локально, автоматической публикации нет. CI остаётся возможным следующим шагом; для него потребуются read-only permissions и отдельная проверка на чистом runner.
