# Формат метрик

CSV в UTF-8, разделитель — запятая, десятичный знак — точка, строки LF. Один заголовок на файл. Дата имени файла определяется временем снимка в UTC, а не временем записи. При повторном открытии непустого файла строки дописываются без повторного заголовка. Файлы предназначены для единственного экземпляра плагина; не редактируйте их во время сбора.

| Поле | Единица и источник | Ограничения |
| --- | --- | --- |
| timestamp_utc | ISO 8601 UTC, Instant.now() | Системные часы могут корректироваться |
| elapsed_ms | мс от начала сессии, разность System.nanoTime() | Сбрасывается при каждом включении сборщика; не зависит от перевода часов |
| tps_1m | тиков/с, Server.getTPS()[0] | Усреднённое Paper значение за 1 минуту, не за интервал сбора; без дополнительного ограничения до 20 |
| mspt_avg | мс/тик, Server.getAverageTickTime() | Среднее из внутреннего окна Paper, а не за интервал сбора |
| players_online | число, размер Server.getOnlinePlayers() | Только агрегат, имена и UUID не сохраняются |
| jvm_heap_used_bytes | байты, MemoryMXBean heap used | Включает ещё не собранный мусор; не RSS, не off-heap |
| loaded_chunks | число, сумма World.getChunkCount() по мирам | Текущие загруженные чанки, без загрузки новых сборщиком |
| entities_total | число, сумма World.getEntityCount() | Все сущности, учтённые API миров, не только живые |
| block_entities_total | число, сумма World.getTileEntityCount() | Block entities, не только тикающие; не входят отдельной категорией в entities_total |
| jvm_heap_committed_bytes | байты, MemoryMXBean heap committed | Память heap, предоставленная JVM; не максимум heap и не RSS |
| gc_collection_count | число сборок, сумма GarbageCollectorMXBean.getCollectionCount() | Накопительное с запуска JVM, не за интервал |
| gc_collection_time_ms | мс, сумма GarbageCollectorMXBean.getCollectionTime() | Приблизительное накопительное время GC; не точное время пауз сервера |

## Схема v2 (TickSense 0.2)

Первые шесть столбцов сохранены в исходном порядке; новые шесть добавлены в конец. Файлы новой схемы называются `metrics-v2-YYYY-MM-DD.csv`, прежние `metrics-YYYY-MM-DD.csv` не изменяются. Writer проверяет точное совпадение заголовка непустого v2-файла до дописывания; несовпадение останавливает сбор с ошибкой вместо смешивания схем. Суточная UTC-ротация и продолжение после перезапуска сохраняются.

GC-счётчики читаются через ManagementFactory.getGarbageCollectorMXBeans(). Недоступные значения (-1) исключаются из сумм независимо для count и time. Если ни один collector не поддерживает поле (или список пуст), записывается -1. Частичная сумма отражает только доступные collectors. Значение 0 означает доступный нулевой счётчик. Эти счётчики относятся к жизни JVM, а elapsed_ms — к сессии сборщика; перезапуск плагина не обнуляет GC. Значения разных MXBeans читаются последовательно.

Состояние миров считывается только в синхронном scheduler, прямыми методами количества, без перечисления сущностей/чанков. Интервал по умолчанию остаётся 200 тиков, обработка настройки interval-ticks не меняется. На реальном Paper необходимо проверить соответствие мировых счётчиков ожидаемому состоянию (включая загрузку/выгрузку миров и чанков), доступность GC для выбранной JVM и накладные расходы. Компиляция и unit-тесты их не измеряют.

Все серверные показатели читаются в синхронном scheduler; это последовательные чтения, а не атомарный снимок JVM. Первый снимок — после interval-ticks с момента готовности конфигурации. 200 тиков соответствует примерно 10 секундам при 20 TPS; при лагах интервал реального времени растёт. При паузе сервера scheduler тоже может не выполняться. Это выборочные измерения, они не обнаруживают каждый медленный тик. Переполнение очереди создаёт пропуски; число потерь видно в журнале, отдельных строк о потерях в CSV нет.

После перезапуска elapsed_ms начинается заново даже в том же дневном файле. Идентификатора сессии в текущей схеме нет. Завершённые строки сохраняются при штатном закрытии; гарантии fsync и восстановления после аварийного обрыва строки отсутствуют.
