# Эксперимент совместимости Paper (не официальная поддержка)

Ветка `feature/paper-compatibility`; отдельный JAR `build/libs/TickSense-0.8.1-compat-test.jar`. Pilot JAR не заменяется. Сборка: `gradlew.bat test build` (без clean, чтобы сохранить прежний артефакт).

Окружения создаются **только** в `C:\Users\Admin\Desktop\Development\TickSense-Compatibility`. Другие серверы/проекты скрипт не ищет и не использует. Сборки закреплены в `paper-builds.json` по официальному API Paper v3 и SHA-256; автоматического выбора latest при запуске нет. Разрешён только официальный download host fill-data.papermc.io.

Из корня репозитория, PowerShell, Python 3.10+ и Java 21 в PATH:

```powershell
.\scripts\test-paper-compatibility.ps1 -Mode Prepare -PythonExe .\venv\Scripts\python.exe
```

Prepare скачивает JAR, проверяет SHA, устанавливает только экспериментальный TickSense, задаёт loopback 127.0.0.1, уникальные порты 25611–25614, online-mode=true, без RCON/query, view/simulation distance=2. Память серверов при последующем Run: 256–1024 MiB heap. Для Run используйте Python с установленными зависимостями существующего анализатора (проверяется импорт analysis.data); они нужны для подтверждения session_id. Windows процессы запускаются без отдельного видимого окна.

**EULA никогда не принимается скриптом.** Если `eula.txt` отсутствует или не содержит `eula=true`, результат BLOCKED; Java-процесс даже не стартует. Владелец должен самостоятельно ознакомиться с [Minecraft EULA](https://aka.ms/MinecraftEULA) и принять решение. Создавать/менять эти файлы за владельца без его предварительного согласия запрещено. Это отдельный шаг от разрешения скачать JAR или запустить сборку.

После согласия и подготовки eula.txt в каждом из четырёх тестовых каталогов:

```powershell
.\scripts\test-paper-compatibility.ps1 -Mode Run -PythonExe .\venv\Scripts\python.exe
```

Порядок строго 1.21.1 → 1.21.4 → 1.21.8 → 1.21.11, только один Paper-процесс за раз. На версию — два запуска: до 240 с ожидания готовности, 45 с наблюдения после готовности, команда stop и до 60 с завершения. При зависании завершается только процесс, созданный этим скриптом; оставшиеся логи сохраняются. Если остановку подтвердить не удалось, следующие серверы не запускаются. Lock-файл предотвращает параллельные экземпляры harness. После аварийного прекращения самого harness не удаляйте lock наугад: сначала проверьте состояние его тестового процесса.

Проверяются enable/disable TickSense, ошибки совместимости/потоков, exit code, 12 полей, UTC, числовые типы, допустимость GC=-1, как минимум 3 строки в каждом запуске, append без второго заголовка и новый session_id существующего анализатора. Начальный MSPT=0 допустим. При переходе UTC-дня проверка сброса внутри одного файла может быть не применима: это нужно разобрать отдельно, а не объявлять поддержку неподтверждённой только из-за границы дня.

Это smoke-тест пустого сервера с проверкой каталогов стандартных миров, **не управляемая нагрузка**, не проверка отдельных вкладов миров и не измерение накладных расходов. Другие версии 1.21.x не покрываются автоматически. PASS относится только к точным сборкам manifest и одному SHA TickSense.

Результаты: `results/compatibility-report.json`, `results/compatibility-summary.md`; полные журналы и CSV — в соответствующих каталогах серверов. Существующие серверные JAR с другим SHA, чужие плагины, результаты с прежними console.log/CSV не перезаписываются. При повторном эксперименте сначала согласуйте ручное архивирование результатов; скрипт не удаляет окружения. Prepare может обновлять сводный отчёт о подготовке, Run — сводку испытаний.

Для восстановления после ошибки **валидации**, когда первый серверный запуск уже завершён штатно, предусмотрен `-Mode Run -Resume`. Он использует сохранённый `first_run.status=PASS`, совпадающие SHA плагина и build Paper, заново проверяет CSV и выполняет только второй запуск. Старые журналы и CSV не удаляются. Если второй запуск уже проводился, его журнал не перезаписывается: требуется отдельное согласованное архивирование. Первоначальную сводку следует сохранить отдельно перед resume. Это не обход неуспешного серверного запуска.

Java Instant может записывать 9 знаков после десятичной точки времени. Для Python 3.10 валидатор укорачивает дробную часть до микросекунд только в копии строки для datetime.fromisoformat; исходный CSV и данные существующего анализатора остаются без изменений.

Статусы: PASS — реально выполнено; FAIL — тест выявил ошибку; NOT TESTED — не выполнялось; BLOCKED — отсутствует разрешение/зависимость или сработала защита. При отсутствии EULA все проверки запуска остаются NOT TESTED и общий статус версии BLOCKED. Это не отрицательный результат совместимости.

Проверка harness без запуска серверов:

```powershell
python -m unittest discover -s scripts -p "test_*.py" -v
```

Корень матриц 1.21.x и 26.x по умолчанию — внешний `TickSense-Compatibility` рядом с проектом. Для структуры `Development/TickSense/TickSense` используется `Development/TickSense-Compatibility`. Переопределение — `--workdir` в Python CLI или `-WorkDir` в PowerShell-обёртке. Корень внутри checkout отклоняется. Существующие каталоги серверов используются повторно. Сводка 26.x записывается отдельно в `results/26/`. [Инструкция для Paper 26.x](../docs/minecraft-26x.md).
