# Анализ метрик TickSense

MVP обучает Isolation Forest на первом CSV, затем строит отчёт и график исключительно для второго, проверочного CSV. Это исследовательские сигналы аномалий, а не автоматическая диагностика причин лагов.

Команды выполняются из корня репозитория (вложенного `TickSense/TickSense`). Python 3.10+, pandas 2.0+.

## Установка и запуск

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r analysis/requirements.txt
.\.venv\Scripts\python.exe analysis/analyze.py datasets/metrics-2026-10-31.csv datasets/metrics-2026-11-01.csv
```

Запуск с двумя позиционными аргументами сохранён; по умолчанию открывается график проверочного набора. Для работы без интерактивного окна:

```powershell
.\.venv\Scripts\python.exe analysis/analyze.py datasets/metrics-2026-10-31.csv datasets/metrics-2026-11-01.csv --json datasets/report.json --png datasets/report.png --no-show
```

Только текстовый отчёт: те же два пути и `--no-show`. JSON отчёта всегда выводится в stdout; `--json` дополнительно сохраняет его в UTF-8. Для справки: `python analysis/analyze.py --help`. Пути с пробелами заключайте в кавычки. Относительные пути отсчитываются от рабочего каталога. Файлы вывода перезаписываются, отсутствующие родительские каталоги создаются.

Linux/macOS: создайте окружение командой `python3 -m venv .venv`, затем используйте `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`. Также поддерживается `python -m analysis.analyze TRAIN.csv TEST.csv --no-show`.

## Компоненты и алгоритмы

- `data.py`: чтение CSV, проверка обязательных столбцов и конечных числовых значений, разбиение на сессии. Дополнительные поля CSV плагина сохраняются. Пустые и некорректные входные файлы отклоняются, строки не удаляются молча.
- `statistical.py`: порог MSPT = rolling mean + 3 × rolling std. Окно строго 6 предыдущих измерений (`shift(1)`), выборочное стандартное отклонение pandas (`ddof=1`). Аномалия — строгое превышение порога. У каждой сессии отдельное окно; первые 6 строк без порога имеют `stat_anomaly=false`, их количество учитывается через `stat_evaluable_measurements`.
- `isolation.py`: признаки `mspt_avg`, `players_online`, `tps_1m`; IsolationForest с `n_estimators=100`, `contamination=0.05`, `random_state=42`, без масштабирования. Только первый CSV передаётся в `fit`; второй — только в `predict` и `decision_function`. Меньший score означает более аномальное измерение; отрицательный score соответствует ML-аномалии. Доля аномалий проверочного набора не обязана быть 5%.
- `report.py`: количество строк и сессий, средний/максимальный MSPT (мс), количество аномалий обоих детекторов, пересечение (`both`), `only_stat`, `only_ml`, `neither`. Топ-10 минимальных `anomaly_score` среди всех проверочных строк (или все строки, если их меньше 10), с временем UTC, сессией, признаками и флагами. Это сравнение детекторов без истинных меток, не оценка точности.
- `visualization.py`: MSPT, динамический порог, метки двух детекторов и зелёные линии изменения онлайна. Линии не соединяются между сессиями. `--no-show` использует Agg для сохранения PNG без GUI.

Строки обрабатываются в исходном порядке. Новая сессия определяется уменьшением `elapsed_ms`, как в исходном анализаторе. Без идентификатора сессии в CSV нельзя надёжно распознать перезапуск, если первая видимая величина elapsed_ms нового запуска не меньше предыдущей. История между двумя файлами не переносится; даже продолжение сессии в проверочном файле требует 6 строк для прогрева. Алгоритмы и параметры детекторов сохранены.

Описание API модели: [IsolationForest](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.IsolationForest.html).

## Производные признаки (TickSense 0.3)

`features.engineer_features(df)` вызывается после загрузки обоих CSV и определения `session_id`, до детекторов. Возвращает независимую копию с пятью столбцами:

| Столбец | Расчёт |
| --- | --- |
| gc_count_delta | Прирост gc_collection_count |
| gc_time_delta_ms | Прирост gc_collection_time_ms, мс |
| loaded_chunks_delta | Изменение loaded_chunks, включая отрицательное при выгрузке |
| entities_delta | Изменение entities_total, включая отрицательное при удалении |
| heap_used_ratio | jvm_heap_used_bytes / jvm_heap_committed_bytes |

Разности используют только предыдущую строку той же сессии в исходном порядке. Первая строка сессии имеет NaN для разностей. GC -1, пропуск или неконечное значение на любом конце интервала делает прирост неизвестным; уменьшение накопительного счётчика тоже даёт NaN. После сброса следующий корректный интервал считается от нового значения. Отрицательные исходные количества считаются некорректными.

Ratio неизвестен при отсутствии столбцов, нечисловых/неконечных значениях, committed <= 0, used < 0 или used > committed. При отсутствии исходных метрик (CSV v1) соответствующие новые столбцы заполнены NaN, а не нулями. Ничего не заполняется из будущих строк. Эти признаки пока **не входят** в Isolation Forest: список FEATURES, параметры модели, CLI и схема JSON не изменены.

## Сравнение моделей (TickSense 0.4)

Отдельный CLI не меняет `analyze.py`. Пример (из корня репозитория):

```powershell
venv\Scripts\python.exe analysis/compare_models.py --train datasets/metrics-v2-2026-11-01.csv --test "datasets/Dragon Run.csv" --json datasets/model-comparison.json
```

Можно указать несколько файлов после `--train`. Альтернативный запуск — `python -m analysis.compare_models` с теми же опциями. Dragon Run передаётся только в `--test`: не включайте проверочные данные или их копии в обучение. Один и тот же путь в train/test отклоняется; перекрытие содержимого разных файлов автоматически не распознаётся.

Базовые признаки: mspt_avg, players_online, tps_1m. Расширенные: те же плюс loaded_chunks_delta, entities_delta, gc_count_delta, gc_time_delta_ms, heap_used_ratio. Параметры обеих моделей: n_estimators=100, contamination=0.05, random_state=42; масштабирование не добавлено. Для воспроизведения сохраняются SHA-256 входов, версии numpy/pandas/scikit-learn, параметры и признаки. Сохраняйте также порядок train-файлов и версии зависимостей.

Признаки вычисляются отдельно для каждого файла до объединения; окна сессий не пересекаются. Обе модели обучаются и сравниваются на одних и тех же строках с полным конечным расширенным набором. Нули не подставляются. Отчёт содержит total/used/excluded отдельно для train/test, invalid_by_feature и список excluded_rows с именами неизвестных/неконечных признаков. Причины неизвестности определены модулем features: начало сессии/файла, отсутствие исходной метрики, недоступные GC, сброс счётчика, некорректный heap. Счётчики invalid_by_feature могут пересекаться, их сумма не равна числу исключённых строк. Если полных строк нет, status=insufficient_complete_rows и модели не обучаются.

Отчёт содержит количества аномалий, пересечение, случаи срабатывания одной модели и список disagreements с исходным файлом, номером CSV-строки, временем, флагами и scores. Меньшее число аномалий не доказывает улучшения. Без истинной разметки это сравнение поведения, а не точность.

Для сводки событий добавьте `--events datasets/events.json`. Формат:

```json
[
  {"name": "Вход в Незер", "start": "2026-11-01T18:00:00+05:00", "end": "2026-11-01T18:02:00+05:00"},
  {"name": "Переход в Энд", "start": "2026-11-01T13:10:00Z", "end": "2026-11-01T13:12:00Z"}
]
```

Замените время на фактическое. Обе границы включены, timezone обязателен; интервалы переводятся в UTC. Перекрывающиеся интервалы считаются независимо. Для каждого указаны все строки, использованные/исключённые строки и срабатывания моделей. Событие само по себе не является истинной аномалией. Не подбирайте параметры по проверочному набору.

## Эпизоды производительности (TickSense 0.5)

Обычный `analyze.py TRAIN.csv TEST.csv --json report.json --no-show` теперь добавляет секцию `performance_events`, независимо от ML. Остальные поля отчёта и предсказания сохранены; `compare_models.py` не использует этот детектор.

`detect_performance_events(df, high_mspt=50, low_tps=19, elevated_mspt=25, max_gap_seconds=30)` из `performance_events.py` использует строго `mspt_avg > 50`, `tps_1m < 19`, `mspt_avg > 25`. Пороги и предел разрыва задаются параметрами функции; `build_report(..., performance_event_options={...})` позволяет их передать. CLI сохраняет прежние аргументы.

Каждый сигнал группируется отдельно по последовательным подходящим строкам в исходном порядке. Неподходящая строка завершает эпизод этого сигнала. Смена сессии или файла, обратный ход часов, разрыв **больше** 30 секунд завершают все активные эпизоды. Ровно 30 секунд допустимы. Повторяющиеся временные метки допустимы, строки не сортируются. Положительный MSPT и TPS не обязательны: нули валидны, но отрицательные, отсутствующие, нечисловые и бесконечные значения невалидны. Некорректное время или отсутствующий session_id также разрывают эпизод; число таких строк указано в invalid_rows. Отсутствие обязательного столбца — ошибка. Строгая проверка CSV в load_data по-прежнему отклоняет некорректные обязательные поля до запуска детекторов.

Секция содержит thresholds, episode_counts и episodes. В каждом эпизоде: signal, session_id, source_file, start_utc, last_observed_utc, measurements, peak_mspt, min_tps, source_rows, single_observation и observed_span_seconds. CSV-загрузчик сохраняет исходный файл и номера записей с учётом заголовка (первая строка данных — 2; выгрузки плагина не содержат пустых или многострочных записей). При прямом вызове без provenance используются позиции строк + 2 и source_file=null.

observed_span_seconds — только наблюдаемый охват между первой и последней подходящими точками, **не точная длительность лага**. Для одного наблюдения он null и single_observation=true. Мы не предполагаем состояние между выборочными измерениями. Высокий средний MSPT и низкий усреднённый TPS — пороговые сигналы возможного ухудшения, а не доказательство ухудшения игрового опыта. Сигналы могут пересекаться и не объединяются в оценку серьёзности; их количества нельзя складывать как число уникальных эпизодов лагов.

## Объяснения событий (TickSense 0.6)

`explanations.py` добавляет поле `explanation` каждому элементу `performance_events.episodes` автоматически при обычном запуске `analyze.py`. Детектор и независимая регистрация сигналов не меняются. Объяснения — детерминированные шаблоны, без LLM и определения причин.

Структура: description, observed_facts, possible_interpretation, limitations, telemetry_context и копия ссылок/времени/показателей эпизода. Отбор контекста требует совпадения исходного файла, session_id, CSV-строк и временных границ. Будущие измерения не используются. В matched_rows видно, сколько строк сопоставлено.

Агрегация только по строкам эпизода:

- Чанки и сущности: сумма знаковых интервальных изменений (net_delta) и максимум положительного изменения (max_positive_delta). Уменьшение — допустимое наблюдение, включая -1. Чистое изменение не является общим количеством загрузок/созданий.
- GC count/time: сумма доступных неотрицательных интервальных приростов (sum_delta), не длительность лага. Отрицательные значения и NaN не учитываются.
- Heap ratio: минимум и максимум доступных отношений в диапазоне [0, 1], без суммирования.

Каждая метрика содержит available_observations, unavailable_observations, status и способ агрегации. Если доступных значений нет, результаты null, status=unavailable; отсутствующий столбец не превращается в нули. При неполном покрытии суммы описывают только доступные интервалы. Первый прирост может относиться к интервалу, начавшемуся до первой точки эпизода: это не утверждение об активности исключительно внутри его временных границ. Для CSV v1 контекст новых метрик недоступен, но пороговые факты остаются.

Ни совпадение изменений с сигналом, ни несколько пересекающихся сигналов не доказывают причинность, несколько независимых проблем или ухудшение игрового опыта. Точная длительность лагов из этой выборочной телеметрии не определяется. CLI, формат CSV, ML и статистический детектор сохранены.

## Автономная панель (TickSense 0.7)

```powershell
venv\Scripts\python.exe analysis/analyze.py datasets/metrics-2026-10-31.csv datasets/metrics-v2-2026-11-01.csv --html datasets/dashboard-118ms.html --json datasets/dashboard-118ms.json --no-show
venv\Scripts\python.exe analysis/analyze.py datasets/metrics-v2-2026-11-01.csv "datasets/Dragon Run.csv" --html datasets/dashboard-dragon.html --no-show
```

Откройте полученный HTML двойным щелчком в современном браузере: это один файл, работающий через `file://` без Python, сервера или интернета. CSS, JavaScript и данные встроены; CDN, шрифтов из сети и сторонних библиотек нет. `--html` необязателен и совместим с `--json`, `--png`, `--no-show`. При `--no-show` окно графика matplotlib не открывается; HTML автоматически не запускается.

Панель на русском языке: обзор, MSPT/TPS, независимые отметки трёх типов детекторов, события с объяснениями и отдельная таблица ML-аномалий. Выбор сессии обновляет карточки, графики и списки; сбрасывает масштаб. Колесо мыши масштабирует графики около указателя, обзорный график над MSPT/TPS задаёт общий диапазон, кнопка сбрасывает его. Масштаб меняет графики, но не отбор событий/карточек сессии. Наведение или нажатие показывает ближайшую точку, UTC, MSPT/TPS и флаги. Линии не соединяют разные сессии/файлы. Показатели обзора вычисляются только для выбранных сессий из готовых значений, без повторного запуска детекторов. ML-таблица выводится порциями по 50 строк. Пороговые сигналы не считаются числом независимых проблем; ML score не является вероятностью.

`html_report.py` отдельно подготавливает данные и рендерит шаблон из `dashboard/`. В итоговом файле нет зависимостей от файлов этого каталога. Словарь RU в dashboard.js централизует динамические подписи для дальнейшей локализации. В представлении используются ru-RU, русские склонения и UTC; исходный JSON 0.6 остаётся неизменным. NaN/отсутствующие значения представлены как null или «Данные недоступны». Имена исходных файлов показываются без абсолютных путей. Любые данные вставляются через textContent, JSON экранирует символы HTML и разделители строк; код из CSV не выполняется. CSP блокирует внешние ресурсы и соединения.

Полный отчёт содержит телеметрию: учитывайте это при передаче HTML другим людям. Тесты проверяют генерацию, безопасность, неизменность JSON и русские подписи. Если установлен Node.js, дополнительно выполняется тест логики UI на лёгких DOM/Canvas-заглушках; он не проверяет визуальную вёрстку и не заменяет открытие в браузере. Отрисовка идёт на Canvas без DOM-узла на каждую точку; для очень больших наборов в дальнейшем может потребоваться прореживание. На узких экранах таблица прокручивается по горизонтали.

### Навигация и шрифты (0.7.1)

Два HTML-ползунка заменены обзорным Canvas с подсветкой выбранной области и затемнением остального диапазона. Боковые маркеры изменяют начало/конец, середина переносит окно без изменения ширины. Основные графики можно перетаскивать для перемещения окна; колесо меняет масштаб около указателя. Все жесты поддерживают Pointer Events и pointer capture, отмену и потерю захвата, не допускают пересечения границ и выхода за данные. Минимальная ширина — 24 CSS-пикселя обзорного графика (не меньше 1 мс и не больше полного диапазона). При изменении ширины экрана окно при необходимости расширяется до минимума. Это ограничение управления, не оценка длительности события.

Клавиатура: Tab переводит фокус на «Начало диапазона», «Переместить окно» или «Конец диапазона». ←/→ меняют соответствующую границу или сдвигают окно на 1% полного диапазона; Shift увеличивает шаг до 10%. Home/End перемещают к доступным краям. Значения границ доступны через подписи и статус с UTC, включая миллисекунды. При смене сессии и нажатии «Сбросить масштаб» выделяется весь диапазон. Для пустого набора и одного уникального времени управление отключено; в одиночном случае ось имеет только визуальные отступы ±0,5 с, которые не означают длительность события.

Основной текст — 16 px, вторичные подписи — 14 px, Canvas — 13 px. Единый системный стек: Inter (если установлен), Segoe UI, Arial, sans-serif. Числа используют tabular-nums в DOM. Canvas получает шрифт явно; внешние шрифты и ресурсы не загружаются.

Не смешивайте `--pilot-files` с позиционными TRAIN/TEST. Минимум — 6 обучающих и 2 проверочных измерения; это технический минимум, а не гарантия достаточного обучения. Одинаковое время не попадает по обе стороны границы. Признаки и rolling-статистика рассчитываются причинно перед разделением: только текущие и прошлые строки; обучение Isolation Forest получает исключительно ранний период. Список признаков и параметры моделей сохранены. Графики, события и ML относятся только к проверочному периоду; раздел качества описывает весь переданный период. Доля 70/30 — простая исходная политика, не оптимизированный выбор эталона нормальной работы.

Загрузчик не сортирует и не удаляет строки. Пустой файл, неверный заголовок, неполная строка, повторный заголовок, неверные числа, время без явного UTC и обратный порядок времени останавливают анализ до формирования отчёта. Числовые счётчики должны быть целыми и неотрицательными; для GC допустимо -1 (недоступен). Схемы дневных файлов должны совпадать. CSV v1 поддерживается отдельно, смешивание схем в одном периоде отклоняется.

Точные дубликаты сохраняются с предупреждением; исправлять их следует в отдельной копии с документированием решения. Перекрывающиеся файлы с обратным ходом времени отклоняются. Смена даты не создаёт сессию: новая сессия определяется уменьшением elapsed_ms. Такой признак не позволяет распознать каждый перезапуск; идентификатора запуска в CSV нет.

Разрыв свыше 30 с внутри сессии отмечается как диагностический, а не как доказанный пропуск или лаг. Интервал 200 серверных тиков удлиняется при снижении TPS. Порог совпадает с max_gap_seconds детектора событий. Эпизоды и линии графиков не соединяются через разрывы; производные признаки остаются интервальными, rolling использует предыдущие наблюдения своей сессии. Эпизоды также разделяются на границах исходных файлов для однозначных ссылок на строки; это не новые серверные сессии.

В автономном HTML раздел «Качество данных» показывает период UTC, файлы, строки, сессии, разрывы, максимальный интервал, предупреждения, границу обучения и ограничения. JSON расширен полем data_quality; прежние поля сохранены. В старом режиме качество относится к TEST; оператор отвечает за независимость TRAIN от TEST.

Для разработчика — воспроизводимая синтетика (не реальные данные для обучения Pilot):

```powershell
python analysis/synthetic_pilot.py datasets/synthetic-pilot
python -m unittest discover -s analysis
```

Генератор с seed=42 создаёт 8640 строк CSV v2 за два UTC-дня: онлайн/отсутствие игроков, пики MSPT, снижение TPS, рост чанков и сущностей, перезапуск и разрыв. Повреждения CSV создаются тестами в временных каталогах. Исходные CSV участников храните локально, не добавляйте в Git; передавайте только согласованным способом. При ошибках запросите исходный файл повторно, не восстанавливайте неизвестные значения нулями.

## Интерпретация отчёта (итерация 0.9)

Результаты детекторов не изменены. Секция «Результаты анализа» показывает число пороговых эпизодов, ML-отклонения и статистические отклонения с разными знаменателями. ML оцениваемо при наличии метки и конечного score; статистика — при наличии метки и rolling-порога. Пересечение и объединение меток учитываются отдельно. Нулевой знаменатель означает «данные недоступны», не 0%. Отсутствие пороговых эпизодов не доказывает отсутствия лагов.

Сводка относится ко всему TEST; фильтр сессий управляет обзором и графиками ниже. Полный период, TRAIN и TEST подписаны отдельно. В старом двухфайловом режиме показываются отдельные периоды и их фактические количества; они не объявляются одним непересекающимся периодом.

«Покрытие режимов обучения» показывает пустой сервер (онлайн 0) и сервер с игроками (онлайн >0), доли TRAIN/TEST и ML-метки TEST. Предупреждение появляется, если режим есть в TEST и его доля в непустом TRAIN строго меньше 5%. Это **эвристика представления**, не универсальная граница репрезентативности, не точность модели и не основание для переобучения. Ровно 5% не вызывает предупреждения; пустой TRAIN не даёт фиктивного предупреждения о смене распределения. Ограничение малого объёма обучения отражается отдельно. Концентрация ML-меток может отражать смену режима, а не ухудшение производительности.

Маркеры пороговых событий и статистики включены первоначально, ML — выключены. Переключатели нативных checkbox доступны с клавиатуры, одинаково работают для MSPT/TPS и сохраняются при смене сессии. Они меняют только отрисовку; таблица, подсказки и JSON сохраняют исходные результаты. При статистическом срабатывании подсказка показывает MSPT, rolling-порог и абсолютное превышение. Нового порога практической значимости нет.

JSON дополнен interpretation. Новый слой не меняет прежние поля, формулы, признаки и параметры ML. HTML остаётся автономным. Пример проверки:

```powershell
python analysis/analyze.py --pilot-files "datasets/Dragon Run.csv" --html reports/pilot-0.9-dragon.html --json reports/pilot-0.9-dragon.json --no-show
```

На локальном Dragon Run: TEST 262; ML 97; статистика 12; пересечение 4; объединение 105; пороговых эпизодов 0. Пустой сервер: TRAIN 2/610, TEST 56/262; все 56 пустых TEST-измерений отмечены ML. Эти контрольные значения не встроены в расчёт отчёта. Реальные CSV и HTML не включаются в Git.

Проверка в настоящем браузере через file:// была заблокирована политикой инструмента автоматизации; визуальная проверка и адаптивность на узком экране остаются ручной проверкой. Логика маркеров, подсказок, переключения сессий и навигации проверяется Node-тестами с DOM/Canvas doubles; это не замена браузерной проверке.

Страница начинается с анализируемого периода, короткого итога и минимального TPS, среднего/максимального MSPT. Сразу за ними идут графики с выбором сессии и диапазона. Количества необычных изменений и резких изменений MSPT показаны один раз, ниже графиков; краткое предупреждение об отличающихся условиях работы появляется только при наличии предупреждения о покрытии.

Основная таблица показывает время, MSPT, TPS, онлайн и нейтральное описание состояния. Порядок прежний — наиболее необычные по оценке модели записи первыми, это не рейтинг тяжести лагов. Все оценки и исходные CSV-ссылки сохранены в закрытом блоке «Подробности анализа», вместе с TRAIN/TEST, методикой, покрытием и полными результатами проверки данных. JSON и вычисления не изменены. ## Полная история в HTML

В режиме `--pilot-files` графики, основной обзор, статистические отклонения и пороговые эпизоды теперь относятся ко **всем** входным измерениям. Переход UTC-дня не создаёт сессию: загрузчик сохраняет порядок и определяет сброс elapsed_ms, как раньше. Перекрытия с обратным временем отклоняются; дубликаты сохраняются с предупреждением, не удаляются молча.

Isolation Forest по-прежнему обучается на ранних 70% и предсказывает только для последних 30%. В раннем участке ML-метки и score неизвестны (null в HTML); это не предсказание «норма». Тонкая линия «Начало поиска необычных изменений» показывается только при доступных ML-результатах и только в соответствующей сессии/видимом диапазоне. Таблица ML содержит только проверочные строки; маркеры первоначально скрыты.

Статистика использует те же шесть предыдущих измерений своей сессии и shift(1); первые шесть строк сессии не оцениваются. Разрыв наблюдений разделяет линии и пороговые эпизоды; rolling по-прежнему означает предыдущие наблюдения сессии, а не непрерывное реальное время. Производные приросты также остаются интервальными. Пороговые эпизоды сохраняют прежнее разделение на границах исходных файлов ради однозначных ссылок на строки; это не искусственные серверные сессии.

Обратная совместимость: прежние поля JSON, включая performance_events, interpretation и счётчики детекторов, по-прежнему описывают TEST. Добавлено поле `full_period`: scope (pilot_full либо evaluation_only), measurements, sessions, mspt_avg_mean/max, tps_1m_min, stat_anomalies, stat_evaluable_measurements, performance_events с объяснениями и ml_boundary (время UTC и сессия либо null). HTML выбирает полные события из этой секции. Поэтому число статистических отклонений в HTML может стать больше, без изменения алгоритма. ML-счётчик относится только к участку поиска; пересечение и объединение в технических подробностях остаются показателями TEST.

Старый режим `TRAIN.csv TEST.csv` сохраняет отображение **только TEST**: отдельный TRAIN не добавляется в графики, потому что его период может пересекаться с TEST. Его full_period имеет scope=evaluation_only. Экспорт PNG тоже сохраняет прежнюю область TEST в обоих режимах; расширение касается HTML.

Производительность: точки Canvas рисуются пакетами по стилям, временные метки кешируются; исходные точки и одиночные всплески не прореживаются. Обе ML-таблицы ограничены текущей страницей (50 строк с возможностью показать ещё), а не создают DOM для всех ML-строк сразу. Полная история передаётся в HTML одним массивом. Проверка взаимодействий в настоящем браузере остаётся ручной: file:// ранее заблокирован политикой инструмента; Node DOM/Canvas doubles не измеряют фактическую плавность браузера.
