# TickSense — v0.8.1 Pilot

TickSense помогает изучать производительность Minecraft-сервера: плагин записывает показатели работы, а разработчик анализирует их и возвращает администратору понятный HTML-отчёт с графиками и пояснениями.

**Pilot — ограниченное экспериментальное тестирование, а не стабильный релиз.** Начните с тестовой копии сервера и сохраните резервную копию.

## Что нужно администратору

- **Java 21** и сервер Paper. Экспериментальная сборка 0.8.1 проверена на Paper **1.21.1 / 133, 1.21.4 / 232, 1.21.8 / 60, 1.21.11 / 132**. Это четыре конкретные сборки, не вся линейка 1.21.x. [Сводка валидации](docs/validation-summary.md).

Тот же `TickSense-0.8.1-pilot.jar`, собранный на Java 21, проверен с подключённым игроком на **Paper 26.1.2 #74, 26.2 #135 и 26.3 #244**. Эти серверы работают на **Java 25**. Purpur 26.x и другие сборки Paper 26.x требуют отдельных испытаний. [Матрица совместимости Minecraft 26.x](docs/minecraft-26x.md).
- Доступ к папке `plugins` и возможность перезапустить сервер.
- Свободное место на диске и обычный браузер для просмотра готового отчёта.

**Для участия достаточно готового JAR. Скачивать исходники, устанавливать Python, запускать анализатор или создавать HTML самостоятельно не нужно.** Анализ выполняет разработчик TickSense отдельно от вашего сервера.

## Как проходит Pilot

1. После публикации скачайте `TickSense-0.8.1-pilot.jar` из раздела [Releases официального репозитория](https://github.com/FunGluck/TickSense/releases/tag/v0.8.1). Если файла ещё нет, дождитесь публикации; архивы исходников для установки не нужны.
2. Остановите сервер обычным способом, положите JAR в папку `plugins`, затем запустите сервер снова. Не используйте `/reload`.
3. Убедитесь, что TickSense начал записывать данные: в `plugins/TickSense/data/` появится CSV-файл, который со временем увеличивается. [Как проверить запуск](docs/pilot-guide.md#3-проверьте-что-данные-записываются).
4. Оставьте плагин работать в течение периода, согласованного с разработчиком. Специально создавать лаги не требуется.
5. По завершении найдите файлы `metrics-v2-YYYY-MM-DD.csv` в `plugins/TickSense/data/`.
6. Сохраните копии завершённых файлов и отправьте выбранные CSV разработчику согласованным способом. Ничего не отправляется автоматически.
7. Разработчик обработает данные и пришлёт готовый HTML-отчёт.
8. Сохраните HTML на компьютер и откройте двойным щелчком в браузере. Для просмотра не нужны Python, веб-сервер или интернет.

Подробные шаги, помощь при ошибках и удаление плагина — в [руководстве администратора](docs/pilot-guide.md).

## Что будет в отчёте

[Посмотреть демонстрационный отчёт Dragon Run](https://fungluck.github.io/TickSense/pilot-dragon.html) · [Страница проекта](https://fungluck.github.io/TickSense/). Публикация новой главной страницы ожидает слияния PR и успешного workflow Pages.

Графики MSPT и TPS, периоды необычных показателей и доступные изменения нагрузки: например, количества чанков, сущностей или памяти. Можно выбирать серверные сессии, приближать графики и читать пояснения к событиям.

Отчёт помогает изучать наблюдения, но **не определяет причину лагов автоматически**. Сигнал или необычная точка не доказывают, что игроки испытывали проблемы.

## Какие данные записываются

Время измерения, время с начала сбора, TPS и MSPT, число игроков онлайн, использование памяти Java, количество загруженных чанков, сущностей и блочных сущностей, показатели сборки мусора Java (GC).

Имена, UUID и IP игроков, чат, координаты, инвентари и seed мира плагин не записывает. Однако время и количество игроков могут раскрывать режим работы сервера. Перед передачей проверьте файлы; вы сами выбираете, какие данные отправлять. Полный лог сервера и копия мира для обычного участия не нужны.

## Что важно знать

- Стандартные настройки подходят для начала Pilot — менять их не требуется.
- Запись происходит раз в 200 серверных тиков: примерно раз в 10 секунд при нормальной работе. При лагах ожидание может быть дольше.
- Каждый день по UTC создаётся отдельный CSV. Дата в имени иногда отличается от вашей местной даты.
- Низкие накладные расходы пока не доказаны. Сначала проверьте плагин на тестовой копии сервера.
- Файлы не удаляются автоматически. Следите за свободным местом. При ошибке диска сбор может остановиться, хотя сервер продолжит работать.
- После аварийной остановки, переполнения очереди или ошибки диска часть данных может быть потеряна.

## Помощь и обратная связь

Если данные не появляются или после установки возникли проблемы, свяжитесь с разработчиком способом, согласованным при вступлении в Pilot. Для описания ошибки также есть [GitHub Issues](https://github.com/fungluck/TickSense/issues). Укажите версию Paper, Java и TickSense, что произошло и когда. Не публикуйте приватные CSV и полный серверный лог в открытом доступе.

## Для разработчиков

[Анализ и команды сборки отчётов](analysis/README.md) · [Сводка валидации](docs/validation-summary.md) · [Аудит Pilot](docs/pilot-audit.md) · [Изменения](CHANGELOG.md) · [Описание выпуска](docs/releases/v0.8.1.md).

Пример для разработчика (Python нужен только на машине анализа):

```powershell
python analysis/analyze.py TRAIN.csv TEST.csv --html reports/report.html --json reports/report.json --no-show
```

Исходный код открыт на GitHub для изучения и участия в разработке. Проверки накладных расходов пока не позволяют подтвердить низкое влияние плагина; подробности и незакрытые сценарии приведены в сводке валидации.

Сборка плагина из исходников: `gradlew.bat test build` (Windows) или `sh ./gradlew test build` (Linux/macOS). Участникам Pilot выполнять эти команды не нужно.
